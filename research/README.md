# Статический анализ клиента, Steam build 26144732

Это результаты чтения присланных DLL, **не реализация скинченджера**.
DLL не запускались и не загружались в процесс. Код игры не изменялся.
Бинарные файлы не включены в репозиторий.

## Что проверено

- SHA-256 всех трёх DLL совпал с пользовательским `CS2-client-info.json`.
  Значение Steam build ID взято из этого отчёта, а не определено по PE-заголовку.
- `client.dll`, `engine2.dll`, `schemasystem.dll` имеют формат PE32+ / AMD64.
- Из `client.dll` извлечены девять статических записей классов с 249 полями.
  Для каждой записи проверены отображение адресов в байты файла, диапазоны таблиц,
  уникальность имён полей и положение каждого поля внутри размера класса.
- Все 249 смещений совпали с `output/client_dll.json` проекта
  [a2x/cs2-dumper, коммит 1005c258412a3657ac73ed1a9f84b9cbedddd876](https://github.com/a2x/cs2-dumper/tree/1005c258412a3657ac73ed1a9f84b9cbedddd876).
  Это дополнительная сверка, не подтверждение идентичности DLL: в том источнике
  нет SHA-256 присланного клиента. Его `build_number: 14192` — номер сборки движка;
  он не является Steam build ID `26144732`.

Полный результат, включая SHA-256, секции PE и поля:
[cs2-build-26144732.json](cs2-build-26144732.json).

## Отличие формата служебных записей

У присланного клиента статическая запись класса содержит размер по `+0x20`,
количество полей по `+0x24` и указатель таблицы полей по `+0x30`.
В изученном коммите `4367fa2b0d2ee4a62e504fbab518a428151b9f9f` проекта
a2x/cs2-analyzer используются другие позиции: `+0x18`, `+0x1C`, `+0x28`.
Поэтому старый формат не использован автоматически. Эти позиции описывают
служебную запись в файле; их нельзя подменять смещениями игровых объектов.

## Повторение анализа

Нужен Python 3.9+, сторонние Python-пакеты не требуются. Подставьте пути к DLL и
отчёту. Пример для семи основных классов:

```sh
python tools/analyze_client.py --client client.dll --engine engine2.dll --schema-system schemasystem.dll --client-report CS2-client-info.json --output analysis.json
python -m unittest discover -s tests -p test_client_analysis.py
```

Для того же набора девяти классов, что в опубликованном отчёте, передайте:

```text
--class-name C_EconEntity --class-name C_EconItemView --class-name C_AttributeContainer --class-name CAttributeList --class-name CEconItemAttribute --class-name CPlayer_WeaponServices --class-name CCSPlayerController_InventoryServices --class-name C_CSPlayerPawn --class-name CCSPlayerController
```

Скрипт воспроизводит данные модулей и классов. Блок `reference_comparison` в
опубликованном JSON добавлен при отдельной сверке с закреплённым коммитом выше;
скрипт сам не скачивает таблицы из интернета. Неоднозначная или некорректная запись,
выход за границы либо несовпадение с отчётом приводят к ошибке, а не к выдаче
предполагаемых смещений.

## Что остаётся неподтверждённым

Не реализованы получение действующих объектов клиента, изменение параметров,
пересоздание материалов, смена моделей ножей/перчаток/агентов, жизненный цикл
динамических атрибутов и восстановление состояния после смены карты или смерти.
Не проверено, какие изменения клиент или сервер перезапишет при синхронизации.
Нет запуска CS2 на доступной Windows-машине, поэтому эти DLL и тесты анализатора
не подтверждают работу в игре, Premier или матчмейкинге.

Кнопка применения в редакторе остаётся недоступной: наличие таблицы полей не
является основанием показывать успешное применение предмета.
