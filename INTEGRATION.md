# Экспериментальная интеграция 0.4.0

Реализован первый модуль подключения к присланной версии CS2: оружейное покрытие,
seed, wear и фильтр T/CT. **Видимый результат в CS2 ещё не проверен.**
Это сборка для проверки интеграции, не подтверждённый рабочий скинченджер для ММ.

## Установка небольшого обновления

1. Закройте редактор и CS2, если предыдущий модуль уже загружался.
2. Скачайте артефакт `CS2Profiles-integration-update-windows-x64` из успешного
   запуска GitHub Actions. Распакуйте `cs2_profiles.exe` и `cs2_bridge.dll`
   в папку старого редактора с заменой EXE. Папка `previews` остаётся рядом;
   картинки повторно скачивать не требуется.
3. Запустите CS2 и тренировочную карту. Возьмите обычное оружие, например AK-47.
4. В редакторе выберите эту же модель и покрытие. Задайте Wear и Seed,
   отключите StatTrak, очистите Custom name, включите свою команду T/CT.
5. Нажмите **Connect to CS2 (experimental)** в Skins или Settings,
   затем **Apply weapon paint / seed / wear** в Skins.
6. Вернитесь в CS2 и проверьте внешний вид. Для следующего значения снова нажмите
   Apply. Сохранение профиля и перемещение ползунка сами ничего в игру не отправляют.

`Frames` показывает вызовы выбранного обработчика кадра, `Refreshes` — завершённые
вызовы обновления материалов. `Observed item / paint` — прочитанные клиентом ID.
Эти счётчики **не доказывают**, что покрытие отрисовалось правильно. Если результат
не появился, сохраните текст статуса и эти четыре числа вместе со скриншотом оружия.
Если состояние — Waiting, сначала проверьте модель оружия в руках и команду.

## Точная область поддержки

| Параметр | Реализация в этой сборке |
| --- | --- |
| Покрытие существующего оружия | Запись fallback-полей, временные косметические атрибуты, вызов обновления материалов |
| Seed / Wear | Передача исходных числовых значений в тот же путь обновления |
| T / CT | Ограничение применения выбранной командой |
| Старый/новый меш покрытия | Выбор по `legacy_model` из каталога |
| StatTrak / имя | Применение отклоняется с объяснением |
| Замена модели ножа / перчаток | Не реализована |
| Агенты / музыка / наклейки / брелоки | Превью и сохранение в профиле, без применения в игре |
| World | Только профиль, без применения в игре |
| Steam-инвентарь | Предметы не добавляются |
| ММ / Premier | Не проверено |

## Версия клиента

Поддержка привязана к трём SHA-256 из присланного отчёта Steam build **26144732**:

```text
client.dll       ccaf4e4926babc052994502b19ec61198a11008a39dce712921b93dd993be9f5
engine2.dll      e8533af07adc3426eac95391cb70804a0a27f8391c03d36f1cfa06f50d901d29
schemasystem.dll 2d2d04c4aa2ed8aca1c9b57f3f0d82278907e898156c417a2dd38f48c63c44f0
```

Другие версии отклоняются до загрузки модуля. После загрузки модуль повторяет
проверку и сверяет первые байты используемых функций. Обновление CS2 требует нового
анализа: отключать проверки ради обхода несовпадения нельзя.

## Восстановление и ограничения

**Restore original weapon** запрашивает восстановление сохранённых полей и мешей
с обновлением материалов. При закрытии редактора или отсутствии heartbeat более
пяти секунд предусмотрено то же восстановление на следующем подходящем кадре.
Пока игра не вызывает этот обработчик, команда остаётся ожидающей.
После нативного исключения модуль прекращает работу; автоматическое восстановление
материалов уже не обещается. Перезапустите CS2 перед повторным подключением.

Модуль загружается обычным Windows LoadLibrary и остаётся в процессе до выхода
из игры, чтобы обработчик кадра не указывал в выгруженную DLL. Обход античита
и скрытие модуля не реализованы; совместимость с VAC и отсутствие санкций не
подтверждены. Ошибка в исследованном вызове может завершить игру. Первый тест
проводите на тренировочной карте.

Чтобы не освобождать память, которую потенциально использует асинхронная
подготовка материалов, модуль сохраняет временные буферы до выхода из CS2.
После 256 обновлений требуется перезапуск игры. Жизненный цикл рендера, повторная
синхронизация с сервером, смена карты и смерть игрока требуют проверки в CS2.

## Что проверяют автоматические тесты

Проверяются отбор допустимых команд, соответствие модели и покрытия каталогу,
диапазоны Wear/Seed, отказ от неподдержанных параметров, сборка атрибутов без
изменения исходного массива, протокол обмена, SHA-256 и отказ DLL от установки
обработчика в процессе без подходящих модулей CS2. Дополнительно выполняются
прежние проверки профилей, каталога, всех картинок и запуска окна.
Игра в CI не запускается; эти тесты не подменяют визуальную проверку.
